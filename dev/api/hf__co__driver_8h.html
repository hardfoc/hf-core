Detailed Description

C interface of the generic CANopenNode driver (CO_driver_hardfoc.c).

One CANopenNode CO_CANmodule_t fans out to up to HF_CO_MAX_PORTS CAN ports. A port is any transport that can send a frame without blocking and report received frames: the TWAI controller (EspTwaiPort), SocketCAN (LinuxSocketCanPort), the host pipe bus (PipePort), later FDCAN and the wireless tunnels. C++ ports implement hf::can::ICanPort (HfCanPort.h) and are attached with hf::can::CoPortBinding (HfCoPortBinding.h); this header is the C seam underneath.

Threading contract:

  • hf_co_driver_rx_push() and hf_co_driver_tx_done() are ISR-safe and lock-free. Each port has its own single-producer ring, so one port must push from one context (its ISR or its reader thread).
  • Received frames are dispatched to CANopenNode from CO_CANmodule_process() (called by CO_process()) or from hf_co_driver_rx_drain(), in thread context. CANopenNode's RX callbacks therefore never run in an ISR.
  • CO_CANsend() hands the frame to every port inside the stack's CAN-send lock. Port send callbacks must not block. A port that answers "queue full" keeps the frame pending in its CANopenNode buffer; it is re-sent in buffer (priority) order from CO_CANmodule_process(), which the port can request at once with hf_co_driver_tx_done().
  • The CO locks (CAN send, EMCY, OD) are one recursive mutex per CANmodule (FreeRTOS or pthread). Nothing that can block is ever called while it is held.

Error status: CO_CANmodule_process() reads every port attached with HF_CO_PORT_ERROR_SOURCE and maps TEC/REC/bus-off and RX overruns to the CO_CAN_ERR* bits that CO_Emergency turns into EMCY messages. A bus-off port gets its recover callback (for EspCan: RequestBusRecovery()), repeated every HF_CO_BUSOFF_RETRY_CALLS process calls while it stays bus-off.
